# Меню: разрушительная самопроверка — 6 ноября 2026

Установка: меню считается неудобным и не соответствующим правилам, **пока не доказано
обратное**. Отдельно проверялись мои собственные правки предыдущего прохода.

Метод: живые замеры в браузере, разбор каскада CSS, стенд состояний
(`qa/next-step-states.html`), сверка с тестами.

## 1. Что проверено и обвинение не подтвердилось

Фиксирую честно, потому что это тоже результат.

| Проверка | Результат |
| --- | --- |
| Семантика вкладок станции | **Корректна.** У каждой вкладки `aria-controls` указывает на существующую панель (`base-panel-summary`, `…-operations`, `…-hangar`, `…-development`, `…-network`), панель имеет `aria-labelledby`, ссылка резолвится, `role="tablist"` подписан («Разделы станции»), roving tabindex работает (выбранная `0`, остальные `-1`) |
| Контраст основного текста | **Выше нормы:** кикер 9.59 : 1, абзац 10.35 : 1, заголовок 16.31 : 1 |
| Главное действие блока «что сейчас важно» | **Читаемо:** кремовая кнопка, контраст 13.82 : 1, высота 41 px |
| Сенсорные цели на 390×844 | **0 кнопок ниже 44 px** (было 6) |
| Иерархия заголовков | У диалога есть `h2` с названием станции, секции панелей используют `h3` — разрыва нет |

Замечание: первая версия замера `aria-controls` показала чужую панель
(`settings-pane-audio`) — это была ошибка моего селектора, который брал первую
выделенную вкладку в документе, а не в станционном `tablist`. После уточнения
семантика оказалась правильной.

## 2. Что провалилось в моих собственных правках

### 2.1 Кремовая кнопка перекрывала «золото» награды

У блока есть состояния `reward` и `return` со своими стилями кнопки. Моё правило
`:first-of-type` перебивало их по специфичности, и награда перестала выглядеть наградой.

**Исправлено:** правило ограничено обычным состоянием —
`:not(.reward):not(.return)`.

### 2.2 Хуже: вариант награды был сломан не мной, а до меня

Стенд `qa/next-step-states.html` показал, что кнопка «Забрать награду» **прозрачная
с почти чёрным текстом**. Причина — то же правило проекта:

```css
#overlay .base-dialog .base-next-actions button { background: initial !important; }
```

Оно стоит позже и перебивает родной золотой стиль
`#overlay .base-next-step.reward button { background:#f2ce7c !important }`.
То есть в опубликованной игре экран «заказ выполнен — заберите награду» тоже был
нечитаемым. Раньше это никто не проверял, потому что состояние труднодостижимо.

**Исправлено:** для `reward` восстановлен золотой градиент (`#f0d7a6 → #d0a769`,
тёмный текст, контраст ≈ 6.8 : 1), для `return` — кремовая кнопка.

### 2.3 Две мои ошибки измерения

Записываю, чтобы не повторять:

1. **Градиент вместо цвета.** Я сравнивал только `background-color` и получил
   «1.36 : 1» у кнопки, которая на самом деле залита градиентом. Правильно читать
   ещё и `background-image`.
2. **Стенд без версии в ссылке.** `qa/next-step-states.html` подключал
   `menu-rebuild.css` без `?v=…`, браузер отдавал старый файл из кеша, и правка
   «не применялась». В этом проекте кеш — хроническая ловушка: версия в ссылке
   обязательна и для стендов.

## 3. Что сознательно не менялось (с доказательствами)

| Находка | Почему не правлю |
| --- | --- |
| Склонения: «15 сплава» вместо «15 сплавов», «1 сплава» | Это системная копирайтинг-политика проекта: **25 утверждений в тестах** фиксируют формы «14 ед. сплава», «24 сплава», «4 сплава», «20 сплава». Правка потребует менять тесты и всю копию сразу — это решение владельца, а не правка вёрстки |
| Причина блокировки не связана с кнопкой программно (`title`/`aria-describedby` отсутствуют) | Добавление атрибута ломает 3 теста, которые сравнивают разметку вида `disabled>метка`. Нужен отдельный подход (`aria-describedby` с id + обновление тестов) |
| Дубли путей: `baseMap` дважды на «Главной», `baseContours` на двух вкладках, две неразличимые `acceptContract` | Продуктовое решение: какие входы основные |
| Жаргон: «Архив данных», «В сети», «Флот», «Флюкс» | Требует решения, какие термины объяснять и где |

## 5. Остаётся проверить

- Живое состояние `reward` в игре (нужен выполненный заказ) — проверено на стенде,
  не на реальном прохождении.
- Фокус-кольцо внутри блока после смены цветов: правка не касается `outline`,
  но отдельного замера не было.
- Светлая тема: в проекте её нет, поэтому кремовая заливка проверена только на тёмном.

## 6. Клавиатура: проверено вживую, дефектов не найдено

Прогон реальными нажатиями: 22 × Tab, затем стрелки, Home/End, Escape.

| Проверка | Результат |
| --- | --- |
| Фокус не выходит за пределы диалога | Все 22 остановки внутри терминала |
| Видимое фокус-кольцо | `outline: solid 1.75px` на каждой остановке |
| Обход по кругу | После последней кнопки фокус возвращается на вкладку «Главная» |
| Переключение вкладок стрелками | `ArrowRight` → «Задания» → «Корабль»; `ArrowLeft` назад; `Home` → «Главная»; `End` → «Станция» |
| Escape | Закрывает терминал и возвращает фокус в игровое поле (`CANVAS`) |
| Roving tabindex | Tab попадает только на выбранную вкладку, остальные `-1` — как требует шаблон ARIA |

Это значит, что четыре из пяти вкладок не «теряются» для клавиатуры: они доступны
стрелками, а не Tab. Типичная ошибка такого рода здесь отсутствует.

## 7. Что из этого следует

Установка «меню плохое, пока не доказано обратное» дала два реальных дефекта
(невидимое главное действие в обычном состоянии и в состоянии награды) и один
собственный промах (кремовый CTA перекрывал золото награды). Всё три исправлены.

При этом три обвинения **не подтвердились** и подтверждены замерами: семантика
вкладок, контраст основного текста, клавиатурная навигация. Это тоже результат:
переделывать там нечего, и лучше это знать, чем переписывать работающее.
