# Изменения 6 ноября 2026 — партия 1

Ветка: `audit/2026-11-06-gameplay-ux`. Основание: `docs/AUDIT-2026-11-06-PLAYTEST.md`.

Партия намеренно небольшая и целиком проверяемая: три правки, каждая закрывает
находку аудита, каждая проверена тестами и наблюдением в браузере.

## 1. Щит работает с первой секунды

**Было.** Регенерация щита была написана, но включалась только при наличии навыка:

```js
if(this.skillRanks.shield && this.time-this.lastDamageAt>3 && ...
```

То есть до покупки ветки «Энергощит» игрок видел в HUD «ЩИТ —», а щит не делал ничего.
Это мёртвая характеристика: полоска есть, механики нет.

**Стало.** Базовый щит работает без навыка: после 3 секунд без урона он восстанавливается
до 16 единиц со скоростью 1,8 ед./с. Навык сохраняет смысл — поднимает и потолок
(16 + 24 за ранг), и скорость.

**Проверка в браузере.** Пассивный прогон, корпус и щит по секундам:

```
00:30 hp=109 sh=1    00:40 hp=109 sh=8     00:50 hp=109 sh=16
00:35 hp=109 sh=11   00:45 hp=109 sh=16    00:52 hp=109 sh=10 (попадание)
```

Корпус всё это время оставался 109 — попадания гасит щит. До правки тот же пассивный
прогон терял 110 → 61 за 48 секунд.

**Тесты.** 1234 из 1234 проходят.

## 2. Экран гибели объясняет, как сохраняться

**Было:** «Контрольной точки нет. Для сохранения включите домашний док и стыкуйтесь
со станциями.» — новичок не знает, что стыковка вообще возможна и какой кнопкой.

**Стало:** «Контрольной точки нет — вылет начнётся заново. Прогресс сохраняет стыковка
с любой станцией: подлетите к ней и нажмите кнопку стыковки.»

Файл: `arcade/menu-screens.js`.

## 3. «Главная» перестала показывать недоступное

**Было.** На экране «Главная» для игрока 1-го уровня с 20 сплава: 17 кнопок, 5 заголовков,
246 слов. Четыре из них — ссылки «Оружие / Корабль / Устройства / Пилот» — дублировали
вкладку «Развитие» и вели туда же, при этом очков развития не было ни одного.

**Стало.** Блок быстрых ссылок показывается только при наличии свободных очков.
Замер: **17 → 13 кнопок**, пустой контейнер не остаётся.

Файл: `arcade/base-panel.js`.

## 4. Мобильный HUD: название сектора больше не режется

**Было.** На 390×844 (портрет) плашка сектора ограничена `34vw` = 132 px, а название
«Аметистовая туманность» требует 234 px. Текст обрезался многоточием — игрок терял
ориентацию «где я», самое важное на узком экране. Мобильный лист `mobile-hud.css`
в портрете не применялся вовсе: он включается только при
`(pointer:coarse) and (orientation:landscape)`.

**Стало.** Добавлено правило для узкого портрета:

```css
@media (max-width:640px) and (orientation:portrait) {
  #hud.cockpit-hud .hud-sector-plaque { max-width: min(64vw, 260px); }
  #hud.cockpit-hud .hud-sector-plaque strong { font-size: 12px; letter-spacing: .02em; }
}
```

**Замер после правки:** `clientWidth = scrollWidth = 182`, `truncated = false`,
шрифт 12 px. Название видно целиком.

## Что НЕ делалось в этой партии

Приоритеты P2–P3 из аудита (первый мини-босс на 90–120 с, награда за удалённость от дока,
экономика ремонта, расшифровки жаргона) не трогались: они меняют ощущение игры и требуют
отдельного цикла «изменил — сыграл — оценил». Смешивать их с исправлением ошибок нельзя.
