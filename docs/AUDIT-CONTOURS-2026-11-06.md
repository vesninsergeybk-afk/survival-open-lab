# Контуры разрушительного аудита «Выжившего» и цели качества

Дата: 6 ноября 2026. Репозиторий: локальный клон `survival-open`, ветка `audit/2026-11-06-gameplay-ux`.
Публикация не затрагивается.

## Установка

Игра считается **скучной, неясной и неотполированной, пока не доказано обратное**.
Каждое утверждение должно опираться на файл и строку, на замер или на внешний источник.
Оценка без доказательства — не результат, а гипотеза, и помечается как гипотеза.

## Цели качества (что значит «хорошая игра» здесь)

Игра — браузерная космическая аркада с автострельбой, добычей, станциями и прокачкой.
Критерии, по которым её судим:

| Цель | Измеримый признак |
| --- | --- |
| Понятно за 60 секунд | новый игрок без подсказок начинает двигаться и стрелять; первая цель ясна |
| Осмысленный выбор каждые 20–30 с | есть решение с разными последствиями, а не только «лететь вперёд» |
| Рост силы заметен за 3 минуты | игрок чувствует разницу до/после первого улучшения |
| Пик напряжения каждые 2–3 минуты | событие, которое замечают без текста |
| Нет мёртвого времени | нет отрезков >20 с без события, цели или решения |
| Неудача учит | после смерти понятно, что сделать иначе |
| Хочется ещё один вылет | есть видимый прогресс между вылетами и рекорд, к которому тянутся |
| Читаемо | HUD и меню читаются на 390 px и на 1366 px, контраст ≥4.5:1 |
| Работает | 60 FPS на среднем устройстве, без ошибок в консоли |
| Целостно | один художественный стиль, один аудиоязык, одна система терминов |

## Контуры аудита

Каждый контур проверяется отдельно: что должно быть по канону жанра, что есть по коду,
в чём расхождение, насколько уверены.

| № | Контур | Что проверяем | Основные файлы |
| --- | --- | --- | --- |
| K1 | Кор-луп и форма сессии | что игрок делает в первые 60 с, 5 мин, 30 мин; есть ли петля «риск → награда → рост» | `game.js`, `opening-arc.js`, `balance.js`, `encounters.js` |
| K2 | Кривая сложности | расписание угроз, пределы врагов, когда появляются типы, есть ли пики и передышки | `balance.js`, `encounters.js`, `ai.js` |
| K3 | Прогрессия | опыт, уровни, кристаллы, ветки навыков, специализации оружия, доктрины, мастерии | `experience.js`, `field-evolution.js`, `ship-loadout.js`, `weapon-specializations.js`, `skill-tree.js`, `development-panel.js` |
| K4 | Экономика | источники и стоки сплава/данных/флюкса; цены; ремонт; награды; инфляция | `balance.js`, `combat-rewards.js`, `base-panel.js`, `experience.js` |
| K5 | Бой и оружие | 7 модулей: роль, дистанция, контр-игра, ощущение удара, ручной/авто режим | `ship-weapons.js`, `weapon-fx.js`, `combat-feedback.js`, `combat-targets.js` |
| K6 | Враги и ИИ | 6 типов: роль, читаемость, угроза, обучение ИИ, коллективное поведение | `ai.js`, `enemy-*.js` |
| K7 | Мир и пространство | регионы, станции, контуры, события мира, смысл лететь куда-то | `regions.js`, `region-runtime.js`, `contour-*.js`, `territory-system.js` |
| K8 | Задания и операции | типы, цели, награды, понятность условия, отмена | `operations.js`, `base-panel.js`, `mission-feedback.js` |
| K9 | HUD | минимальность, иерархия, читаемость под давлением, шум | `hud.js`, `hud.css`, `hud-art.css`, `mobile-hud.css` |
| K10 | Меню и потоки | количество решений, дубли путей, состояния, клавиатура, мобильный | `base-panel.js`, `menu-*.js`, `hangar-panel.js`, `map-panel.js` |
| K11 | Подача: VFX, арт, звук | ощущение удара, взрывы, читаемость эффектов, музыка и переходы, целостность стиля | `combat-feedback.js`, `weapon-fx.js`, `tactical-vfx.js`, `visuals.js`, `audio-director.js`, `music-playlist.js` |
| K12 | Техника и доступность | 60 FPS, мобильные размеры, сохранения, ошибки консоли, a11y | `game.js`, `run-checkpoint.js`, `mobile-*.css`, `qa/` |

## Правила работы с данными

1. Всё, что взято из документов проекта, — это **замысел**, а не факт реализации.
   Факт — только код и наблюдение.
2. Числа берутся из кода или замера, а не из памяти.
3. Если контур не проверен инструментом — так и пишется: «не проверено».
4. Любое «улучшение» должно иметь критерий приёмки и способ проверки.

## Порядок

1. Разведка по контурам (факты, инвентарь, замеры).
2. Руководства: навыки проекта + внешние источники по жанру.
3. Разрушительный разбор по контурам с уровнями уверенности.
4. Перепроверка выводов и полноты (что не проверено и почему).
5. План доработки с приоритетами и критериями.
6. Реализация партиями, каждая — с тестами и наблюдением.
